# TreatyAI → Salesforce Agentforce: Partner Handoff

**Release:** TreatyAI v0.3.0
**Salesforce responsibility:** teammate
**TreatyAI:** local deterministic engine and optional Groq multi-agent negotiation
**Salesforce org:** not connected or deployed

This package includes typed contracts, examples and Salesforce source for your teammate to integrate with Agentforce without modifying the TreatyAI decision engine.

## 1. Architecture and trust boundary

Salesforce Agentforce / CRM
  → Custom Apex action and Named Credential
  → Authenticated HTTPS gateway to TreatyAI
  → POST /api/decisions/coordinate
  → Typed contracts → conflict graph → optimizer → independent verifier
  → Local SQLite transaction → decision receipt → tamper-evident audit

**Do not expose the local FastAPI development server directly to the Internet.** It binds only to 127.0.0.1 and has local demo routes that are not suitable for public deployment.

The external POST /api/decisions/coordinate endpoint has a separate bearer-token gate. It returns HTTP 503 until the environment variable TREATYAI_INTEGRATION_TOKEN contains a strong random secret of at least 32 characters. Invalid or missing credentials return HTTP 401. This credential is entirely separate from the Groq API key.

The bearer authenticates the integration service, not the individual agent. A production Salesforce adapter must map agent identity and customer scope from authenticated Salesforce principals; model-generated agent_id and customer_id fields are never identity proof.

## 2. Included files

- openapi.json — generated from the actual FastAPI app; includes HTTP bearer security scheme

## 3. Request contract

POST /api/decisions/coordinate

Headers:
- Authorization: Bearer [TREATYAI_INTEGRATION_TOKEN] (place in Salesforce Named/External Credential, not code)
- Content-Type: application/json

Body:
- scenario_id: audit label
- customer_id: customer ID derived from authenticated CRM context
- proposals: one to twenty typed DecisionContracts

Each proposal includes its own unique idempotency key, registered agent identity, bounded action and parameters, expected customer-state version, evidence, human-approval flag and rationale.

Never let model text invent permissions, consent, budgets, customer identity or evidence. TreatyAI's demo customer state is synthetic; the Salesforce team must map authoritative org data for any real integration.

## 4. Response meanings

| HTTP | Meaning | Salesforce action |
|---|---|---|
| 200 committed | Verified plan committed to LOCAL SYNTHETIC STATE ONLY | Display recommendation; real Salesforce action is not yet performed |
| 200 awaiting_human | High-impact action needs human approval | Escalate, never automatically execute |
| 200 no_action | No safe action chosen | Report no feasible action |
| 200 halted | Independent verification failed | Do not execute |
| 401 | Integration credential invalid or missing | Correct Named Credential |
| 409 | Idempotency key already processed | Reconcile original receipt, never duplicate the action |
| 422 | Schema or customer mismatch | Fix request |
| 503 | Integration disabled without a service token | Configure secure endpoint |
| 500/502 | Unexpected failure | Fail closed |

The receipt contains policy/engine versions, outcomes, checks and a SHA-256 hash. The hash chain is tamper-evident, not externally signed.

## 5. Salesforce development steps

1. Sign in to the free Salesforce Agentforce Developer Edition.
2. Open the cloud-hosted IDE or an already-installed Salesforce CLI.
3. Import source from salesforce/force-app/.
4. Configure an authorized HTTPS Named Credential named TreatyAI_API.
5. Compile and run TreatyAIGovernanceActionTest in the real org.
6. Expose TreatyAIGovernanceAction.coordinate as an Agentforce custom action.
7. Implement authoritative Account/Contact, Case, consent and compensation mapping.
8. Implement a secure outbox and downstream idempotency before any real external side effects.
9. Test consent denial, shared-budget contention, idempotency replay, stale state and loss of connectivity in a sandbox.

**Apex has not yet been compiled or deployed in Salesforce.**

## 6. Acceptance checklist for your teammate

- Agentforce custom action deployed, configured and visible
- Apex tests passed in the real Salesforce org
- Named Credential authorized and no shared secrets in source
- Correct mapping of agent/customer identity and tenant permissions
- An agent produces a typed request that TreatyAI accepts
- Verified receipt returned from the real HTTPS round trip
- Consent revocation and shared-budget limits enforced end-to-end
- Retries do not duplicate downstream actions
- Synthetic vs real effects clearly labeled in the hackathon demonstration

## 7. Offline fallback

The existing Decision Room, concurrency test and TreatyBench work without Salesforce or Groq. If either external service fails, the local deterministic demonstration still proves global constraints, independent verification and audited transactions.
